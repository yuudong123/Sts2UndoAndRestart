# Undo And Restart 구조 명세

## 목표

이 모드는 STS2 전투 상태를 직접 스냅샷으로 저장하고 복원합니다. QuickRestart처럼 전투 시작부터 재생하는 방식이 아니라, 현재 객체 그래프의 필드와 UI 상태를 되돌려 즉시 이전 상태로 이동하는 방식을 사용합니다.

## 전체 구성

```text
MainFile
  -> Harmony 패치 등록
  -> 설정 로드
  -> CombatManager 이벤트 구독

UndoRedoPatches
  -> 입력 처리
  -> 게임 액션 경계 감지
  -> 입력 설정 항목 주입

UndoRedoManager
  -> 스냅샷 목록 관리
  -> undo/redo 커서 관리
  -> 타임라인 이동 직렬화와 복원 실행 잠금 관리
  -> 폐기된 타임라인 세대의 비동기 콜백 무효화
  -> 플레이어 조작 가능 시점과 선택적 카드 선택 경계 캡처

CardChoiceCheckpointService
  -> 수동 카드 선택창 체크포인트 캡처
  -> 원래 액션을 재실행해 선택창 재구성

CombatSnapshot
  -> 전투, 런, 카드, 플레이어, 크리처, UI 상태 캡처/복원

ActionHistoryOverlay
  -> 사용 기록 UI 렌더링

FloorRestartService
  -> F5 층 다시 시작 처리
```

## 스냅샷 캡처 흐름

1. 카드, 포션, 턴 종료 같은 주요 액션이 시작되면 `UndoRedoPatches`가 `UndoRedoManager.CaptureBeforeAction`을 호출합니다.
2. 액션 Task가 완료되면 `CaptureAfterActionAsync`가 플레이어 조작 가능 시점 캡처를 예약합니다.
3. `ActionExecutor.AfterActionFinished`, `ActionQueueSynchronizer.PlayPhase`, `CombatManager.PlayerActionsDisabledChanged` 같은 경계에서 안정화 여부를 다시 확인합니다.
4. 실제 캡처 가능 조건을 만족하면 `CombatSnapshot.Capture`가 호출됩니다.
5. 일부 값만 비교하는 fingerprint는 사용하지 않습니다. 유물 스택이나 모드 내부 필드만 바뀐 행동도 독립 스냅샷으로 보존합니다.
6. 액션 완료 메타데이터는 정확한 `GameAction`과 연결하고 현재 타임라인 세대의 콜백만 받습니다.
7. 자동 조작 가능 콜백은 redo 브랜치를 자르지 않습니다. 플레이어가 새 액션이나 재생된 선택창의 새 선택으로 실제 분기할 때만 현재 커서 뒤를 제거합니다.

카드 선택창 체크포인트를 켜면 수동 선택 요청도 추가 경계가 됩니다. 카드가
한 장뿐이라 자동으로 처리되는 선택은 제외합니다. 해당 체크포인트를 복원할
때는 먼저 액션 전 스냅샷으로 돌아간 뒤, 대상 선택창이 열릴 때까지만 원래
액션을 재실행합니다. 재실행 중 캡처는 막아서 기존 타임라인이 갈라지거나
잘리지 않게 합니다.

## 복원 흐름

`UndoRedoManager`는 타임라인 이동 요청을 한 번에 하나만 처리합니다. 입력 콜백에서는 `CallDeferred`로 씬 트리 순회만 벗어나며, 다음 렌더 프레임을 기다리지 않고 플레이어 입력과 손패를 잠근 뒤 실행기와 모든 플레이어 큐를 멈춥니다. 카드 선택이 진행 중이면 안전하게 중단하고 액션 런타임이 실제로 안정될 때까지만 기다립니다. 이동 중 추가 방향 입력은 버리지 않고 마지막 요청 하나를 직렬로 이어서 실행합니다. 그 뒤 롤백 스냅샷을 만든 후 `CombatSnapshot.RestoreAsync`를 실행합니다. 대상 복원이나 검증이 실패하면 같은 잠금 안에서 롤백 스냅샷으로 복구합니다.

`CombatSnapshot.RestoreAsync`는 다음 순서로 복원합니다.

1. 추적 중인 이전 타임라인의 비동기 카드 VFX와 소유 카드 노드를 즉시 숨겨 격리합니다. 해당 Task는 격리된 노드에서 자체 생명주기를 끝내며 복원은 기다리지 않습니다.
2. 나머지 일시 카드 VFX를 정리하고, 이전 타임라인의 사망 Task를 가진 크리처 노드를 트리에서 동기적으로 분리해 엔진 취소 토큰을 발동합니다.
3. 크리처 생명주기와 전투 참여 목록을 복원합니다. 다시 필요한 크리처 노드는 모든 모델 복원이 끝난 뒤 새로 생성합니다.
4. 런 상태와 모델 필드를 복원합니다.
5. 전투 필드, 플레이어 상태, 카드 더미, 포션, 유물, 오브를 복원합니다.
6. 전투 히스토리와 런 히스토리를 복원합니다.
7. 카드 UI 갱신 신호를 보내고 유물 활성 표시 상태를 정리합니다.
8. 오래된 플레이 UI를 트리에서 즉시 분리하고 같은 렌더 전 손패를 다시 구성한 뒤 위치와 입력 상태를 스냅합니다.
9. 적 의도 갱신 Task까지 기다린 뒤 스냅샷 검증을 실행합니다.

복원은 게임의 공식 save/load와 다르게 현재 객체를 최대한 재사용합니다. 그래서 Godot 노드, Spine 애니메이션, 카드 플레이 노드, 포션 슬롯, 유물 홀더 같은 UI 상태를 별도로 정리합니다. 풀링되는 노드는 반드시 `QueueFreeSafely`로 반납하며 복원 정리에서 직접 `QueueFree`를 쓰지 않습니다.

크리처 애니메이션은 재생 시각을 스냅샷 상태로 취급하지 않습니다. 트랙 0의 피격·공격·사망 같은 일회성 모션은 버리고 안정 상태로 정규화합니다. 루프 트랙은 애니메이션 이름만 복원하고, 일회성 전환 뒤에 루프가 예약돼 있으면 현재 전환 프레임 대신 예약 큐의 최종 루프를 의미 상태로 저장합니다. 상위 트랙에서 이미 끝난 유지 포즈는 애니메이션 끝점으로 복원합니다. 위치, 형태 VFX, 크기·색 같은 의미 기반 표시 값은 보존하지만 트윈 진행률이나 정확한 Spine 프레임은 보존하지 않습니다.

`NCreature.DeathAnimationTask` 참조를 `null`로 만드는 것은 실행 중인 `AnimDie`를 취소하지 못합니다. 따라서 사망 Task가 남은 노드는 모델 변경 전에 트리에서 분리합니다. 이때 `_ExitTree`가 `DeathAnimCancelToken`을 취소하고 기존 파워·전투 이벤트 구독을 해제합니다. 복원 뒤에는 같은 논리 `Creature`를 사용하는 새 `NCreature`가 생성되므로 이전 타임라인의 콜백이 복원된 체력바나 노드를 건드릴 수 없습니다.

## F5 층 다시 시작 흐름

`FloorRestartService`는 현재 싱글플레이 런 저장 데이터를 읽어 현재 방 입장 상태로 돌아갑니다.

- 멀티플레이어에서는 실행하지 않습니다.
- 액션 큐가 진행 중이면 실행하지 않습니다.
- 전투 보상 화면에서 이미 완성된 추가 보상은 보존합니다.
- 전투 진행 중 생성된 미완료 추가 보상은 재시작 전에 제거합니다.
- 런 씬을 정리한 뒤 저장된 방을 다시 로드합니다.

## 설정과 입력

- 설정 파일: `OS.GetUserDataDir()/mod_configs/UndoAndRestart.json`
- 설정 화면에서 사용 기록 표시와 카드 선택창 체크포인트 사용 여부도 조절합니다.
- 입력 액션:
  - `undo_and_restart_undo`
  - `undo_and_restart_redo`
  - `undo_and_restart_restart`
- 기본 fallback 키:
  - 되돌리기: 왼쪽 방향키
  - 다시 실행: 오른쪽 방향키
  - 층 다시 시작: `F5`

입력 설정에 사용자가 직접 단축키를 지정하면 기본 fallback 키보다 사용자 설정을 우선합니다. 콘솔, `LineEdit`, `TextEdit` 입력 중에는 undo/redo 단축키를 무시합니다.

## 멀티플레이어 차단

모드 매니페스트는 `affects_gameplay=false`입니다. 대신 코드에서 실제 상태 변경 기능을 제한합니다.

- `UndoRedoManager.CanCapture`는 일반 멀티플레이어 런에서 캡처를 차단합니다.
- `FloorRestartService`는 `NetGameType.Singleplayer`가 아니면 F5 재시작을 차단합니다.
- 사용 기록 UI는 싱글플레이 또는 fake multiplayer 조건에서만 표시됩니다.

## 업데이트 시 점검할 부분

- STS2 내부 필드명: reflection으로 접근하는 필드는 게임 업데이트 후 이름과 타입을 다시 확인해야 합니다.
- 액션 안정화 타이밍: 카드 사용, 카드 생성, 포션 사용, 턴 종료 경계에서 플레이어 조작 가능 시점 캡처가 유지되는지 확인해야 합니다.
- 비동기 VFX 소유권: 업데이트마다 fire-and-forget 카드 VFX와 지연 정리 Task가 `TransientCardVfxCleanup`에 포함되는지 비교해야 합니다.
- 복원 잠금: 동기화 상태 갱신이 복원 중 실행기나 플레이어 큐를 다시 열지 않는지 확인해야 합니다.
- 타임라인 콜백: 액션 및 카드 선택 콜백은 세대를 포함하고 폐기된 미래에서 분기하지 않아야 합니다.
- 카드 비용과 런타임 상태: 비용 변경 효과, 이번 턴 한정 비용, 카드 UI 갱신이 함께 복원되는지 확인해야 합니다.
- 유물 스택 표시: 실제 모델 값과 UI 표시 값이 복원 후 같은 상태로 갱신되는지 확인해야 합니다.
- 보상/런 히스토리: F5와 undo가 통계, 피해 기록, 보상 계산에 누적 영향을 남기지 않는지 확인해야 합니다.
